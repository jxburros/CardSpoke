## Overview

Version 0.9 introduces **multi-dataset support** with flexible storage drivers and optional PIN protection. This represents a major architectural shift from single-instance to multi-instance data management.

### Goals
1. Support multiple independent datasets (projects, worlds, workspaces)
2. Allow users to choose storage location (browser, filesystem, future: cloud)
3. Enable per-dataset PIN protection
4. Maintain backward compatibility with 0.8.x data
5. Preserve local-first philosophy

---

## Current Architecture (v0.8.2)

### Data Storage
- **Single instance:** All data in one `localStorage` key
- **Format:** JSON serialization of entire store
- **Key:** `nested_cards_store` or user-created instances
- **Backup:** Manual export to JSON file

### Limitations
- Only one active dataset at a time
- Cannot organize multiple projects separately
- No built-in PIN protection
- Browser storage only (limited capacity)
- No dataset metadata or versioning

## Proposed Architecture (v0.9)

### Dataset Concept

A **dataset** is an independent collection of cards with its own:
- Unique identifier and name
- Storage driver (IndexedDB, localStorage, or file-based)
- Optional PIN protection
- Metadata (created date, size, description)
- Mod configuration

### Multi-Dataset System

```typescript
type Dataset = {
  id: string;                    // Unique identifier
  name: string;                  // User-friendly name
  description?: string;          // Optional description
  storage: StorageDriverConfig;  // Storage configuration
  pin?: PINConfig;              // Optional PIN protection
  createdAt: number;            // Creation timestamp
  updatedAt: number;            // Last update timestamp
  size?: number;                // Estimated size in bytes
  cardCount?: number;           // Number of cards
  schema: number;               // Schema version (4)
};

type StorageDriverConfig = {
  driver: 'indexeddb' | 'localfile' | 'capacitor-preferences';
  config: Record<string, any>;  // Driver-specific config
};

type PINConfig = {
  algo: 'pbkdf2' | 'scrypt';
  salt: string;
  hash: string;
  iterations: number;
};
```

### Dataset Registry

A central registry tracks all available datasets:

```typescript
type DatasetRegistry = {
  version: number;              // Registry schema version
  activeDatasetId: string;      // Currently active dataset
  datasets: Dataset[];          // Array of dataset metadata
};
```

**Storage:** Stored in `localStorage` key `cardspoke_registry`

## Storage Driver Interface

### Abstract Interface

```typescript
interface StorageDriver {
  kind: 'indexeddb' | 'localfile' | 'capacitor-preferences';
  
  // Initialization
  init(config: any): Promise<void>;
  
  // Basic Operations
  get(key: string): Promise<any>;
  set(key: string, value: any): Promise<void>;
  list(prefix?: string): Promise<string[]>;
  remove(key: string): Promise<void>;
  clear(): Promise<void>;
  
  // Backup & Export
  backup?(): Promise<Blob>;
  
  // Metadata
  size?(): Promise<number>;
  keys?(): Promise<string[]>;
}
```

### Implementation Strategy

1. **IndexedDB Driver** (Default for web)
   - Best capacity (~50MB-1GB)
   - Async API
   - Better performance
   
2. **localStorage Driver** (Fallback)
   - Limited capacity (~5-10MB)
   - Synchronous API
   - Universal browser support
   
3. **Capacitor Preferences Driver** (Native apps)
   - Uses Capacitor Preferences API
   - Native storage on device
   - Best for mobile

4. **Future: Filesystem Driver**
   - Direct file access (Capacitor Filesystem)
   - User-specified location
   - Large capacity
   - v0.9.1+ feature

## Data Migration Strategy

### From 0.8.x to 0.9.0

**Automatic Migration on First Launch:**

1. **Detect existing data:**
   ```javascript
   const hasLegacyData = localStorage.getItem('nested_cards_store') !== null;
   ```

2. **Create default dataset:**
   ```javascript
   const defaultDataset = {
     id: 'default',
     name: 'My Cards',
     description: 'Migrated from v0.8',
     storage: { driver: 'indexeddb', config: {} },
     schema: 4,
     createdAt: Date.now(),
     updatedAt: Date.now()
   };
   ```

3. **Migrate data to IndexedDB:**
   ```javascript
   const legacyData = JSON.parse(localStorage.getItem('nested_cards_store'));
   await indexedDBDriver.set('store', legacyData);
   ```

4. **Create registry:**
   ```javascript
   const registry = {
     version: 1,
     activeDatasetId: 'default',
     datasets: [defaultDataset]
   };
   localStorage.setItem('cardspoke_registry', JSON.stringify(registry));
   ```

5. **Preserve legacy data:**
   - Keep original localStorage data for 30 days
   - Add migration flag: `_migrated_to_v0.9`
   - Allow rollback if needed

## Dataset Operations

### Creating a Dataset

```javascript
async function createDataset(name, description, storageType, pin) {
  const dataset = {
    id: uid(),
    name,
    description,
    storage: { driver: storageType, config: {} },
    pin: pin ? await hashPIN(pin) : undefined,
    createdAt: Date.now(),
    updatedAt: Date.now(),
    schema: 4
  };
  
  // Initialize storage driver
  const driver = getDriver(dataset.storage);
  await driver.init(dataset.storage.config);
  
  // Create empty store
  await driver.set('store', createEmptyStore());
  
  // Add to registry
  registry.datasets.push(dataset);
  saveRegistry();
  
  return dataset;
}
```

### Switching Datasets

```javascript
async function switchDataset(datasetId) {
  // Save current dataset
  await save();
  
  // Load new dataset
  const dataset = registry.datasets.find(d => d.id === datasetId);
  if (!dataset) throw new Error('Dataset not found');
  
  // Check PIN if required
  if (dataset.pin) {
    const pin = await promptForPIN();
    if (!await verifyPIN(pin, dataset.pin)) {
      throw new Error('Invalid PIN');
    }
  }
  
  // Load data
  const driver = getDriver(dataset.storage);
  const data = await driver.get('store');
  
  // Update app state
  store = data;
  registry.activeDatasetId = datasetId;
  saveRegistry();
  
  // Re-render
  render();
}
```

### Deleting a Dataset

```javascript
async function deleteDataset(datasetId) {
  if (datasetId === registry.activeDatasetId) {
    throw new Error('Cannot delete active dataset');
  }
  
  const dataset = registry.datasets.find(d => d.id === datasetId);
  if (!dataset) throw new Error('Dataset not found');
  
  // Clear data
  const driver = getDriver(dataset.storage);
  await driver.clear();
  
  // Remove from registry
  registry.datasets = registry.datasets.filter(d => d.id !== datasetId);
  saveRegistry();
}
```

## PIN Protection

### Hashing Algorithm

Use PBKDF2 with high iteration count:

```javascript
async function hashPIN(pin) {
  const salt = crypto.getRandomValues(new Uint8Array(16));
  const iterations = 100000;
  
  const key = await crypto.subtle.importKey(
    'raw',
    new TextEncoder().encode(pin),
    { name: 'PBKDF2' },
    false,
    ['deriveBits']
  );
  
  const hash = await crypto.subtle.deriveBits(
    {
      name: 'PBKDF2',
      salt,
      iterations,
      hash: 'SHA-256'
    },
    key,
    256
  );
  
  return {
    algo: 'pbkdf2',
    salt: arrayToHex(salt),
    hash: arrayToHex(new Uint8Array(hash)),
    iterations
  };
}
```

### PIN Entry UI

- **On Switch:** Prompt for PIN before loading dataset
- **Auto-lock:** Optional timeout (5 min, 15 min, never)
- **Recovery:** No recovery - PIN is local only
- **Export:** PIN-protected exports include PIN hash

## Breaking Changes

### API Changes
- `localStorage.getItem('nested_cards_store')` → Registry system
- Single store → Multi-dataset with active dataset
- Synchronous save → Async save (for all drivers)

### Data Format
- No breaking changes to card schema (still v4)
- Store structure unchanged
- Additional registry metadata

### User Impact
- Must complete migration on first launch
- Existing bookmarks/recent preserved
- Mod configurations migrated
- No data loss

## Backward Compatibility

### Reading 0.8.x Data
v0.9 can read and migrate 0.8.x data automatically.

### Exporting for 0.8.x
Provide "Export as v0.8 format" option:
- Single dataset export
- Remove v0.9 metadata
- Compatible with older versions

### Rollback Support
If user wants to downgrade:
1. Export active dataset
2. Copy JSON to localStorage key
3. Revert to v0.8.x

## Performance Considerations

### IndexedDB Performance
- Async operations (non-blocking)
- Better for large datasets (>100 cards)
- Indexed queries possible (future optimization)

### Memory Management
- Only load active dataset in memory
- Lazy load dataset metadata
- Clear unused drivers from memory

### Storage Capacity
- IndexedDB: ~50MB-1GB (browser dependent)
- localStorage: ~5-10MB
- Capacitor Preferences: Device dependent
- Filesystem: Unlimited (user's storage)

---

## Security Considerations

### PIN Protection
- **Local only:** PIN never transmitted
- **No recovery:** Lost PIN = lost data
- **High iterations:** PBKDF2 with 100k iterations
- **Salted hashes:** Unique salt per dataset

### Data Isolation
- Each dataset completely isolated
- No cross-dataset data leakage
- Separate storage containers

### Export Security
- PIN-protected exports optional
- Unencrypted exports warn user
- No automatic cloud upload
